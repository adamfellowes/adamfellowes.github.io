# CLAUDE.md

This file documents the codebase structure, conventions, and development workflow for AI assistants working on this repository.

## Repository Overview

**adamfellowes.github.io** is a personal GitHub Pages site — a static website hosted directly from the `master` branch. It serves as a playground for web experiments.

Live URL: `https://adamfellowes.github.io`

## File Structure

```
adamfellowes.github.io/
├── index.html              # Main landing page (GitHub Pages auto-generated template)
├── flashcard-test.html     # Standalone flashcard study app
├── sample-flashcards.md    # Example markdown file for the flashcard app
├── params.json             # GitHub Pages generator metadata (do not delete)
├── README.md               # Minimal repo description
├── stylesheets/
│   ├── styles.css          # Main stylesheet (GitHub Pages "orderedlist" theme)
│   └── github-light.css    # GitHub syntax highlighting theme
└── javascripts/
    └── scale.fix.js        # iOS viewport scaling fix
```

## Pages

### `index.html` — Landing Page
- Auto-generated by the GitHub Pages page generator
- Uses the "orderedlist" theme (fixed 860px wide wrapper, 270px fixed sidebar header, 500px content section)
- Loads `stylesheets/styles.css` and `stylesheets/github-light.css`
- Loads `javascripts/scale.fix.js` for iOS scaling
- Content is a standard GitHub Pages boilerplate intro

### `flashcard-test.html` — Flashcard App
A fully self-contained, single-file flashcard study tool with no external dependencies.

**Features:**
- Upload a markdown file to generate flashcards
- Two supported markdown formats:
  - **Format 1 (Headers):** `# Question` followed by answer text on the next lines
  - **Format 2 (Q&A):** `Q: question` / `A: answer` pairs
- 3D CSS flip animation when clicking a card
- Prev/Next navigation buttons
- Keyboard shortcuts: `ArrowRight`/`n` = next, `ArrowLeft`/`p` = previous, `Space`/`f` = flip
- Shuffle button (Fisher-Yates algorithm)
- Persists flashcard data in `localStorage` and prompts to resume on reload
- Gradient background: `#667eea` → `#764ba2`
- All styles are inline `<style>` within the file; no external CSS

### `sample-flashcards.md` — Example Flashcard Data
Uses Format 1 (header-based). Each `# Heading` is the question, the following paragraph is the answer.

## Stylesheets

### `stylesheets/styles.css`
- "Noto Sans" via `@font-face` (references a `../fonts/` directory not present in the repo — fonts fall back to system fonts)
- 14px/1.5 body type, `#727272` body text color, `#222` headings
- Fixed-position sidebar layout: 270px `header` float left, 500px `section` float right, 860px `.wrapper`
- Responsive breakpoints: 960px (stacks columns), 720px (mobile), 480px (small mobile), print
- Link color: `#39c` (hover: `#069`)

### `stylesheets/github-light.css`
- Syntax highlighting styles for code blocks (GitHub Light theme)

## JavaScript

### `javascripts/scale.fix.js`
- Detects iPhone user agent and locks viewport scale on load
- On `gesturestart`, unlocks scale to allow pinch-zoom (min 0.25, max 1.6)
- Legacy iOS workaround — no frameworks, vanilla JS

## Deployment

This is a **GitHub Pages** site deploying from the `master` branch root. There is no build step, bundler, or CI pipeline. Changes pushed to `master` are automatically published.

- No package.json, no Node.js toolchain, no Jekyll config
- No `.nojekyll` file — Jekyll processing is technically active, but there are no Liquid templates in use
- `params.json` is used internally by the GitHub Pages generator and should not be deleted

## Development Conventions

- **No build tools.** All files are static HTML/CSS/JS served as-is.
- **Self-contained pages.** New experiments should ideally be single `.html` files (like `flashcard-test.html`) to avoid dependency entanglement.
- **Inline styles for standalone pages.** New standalone tools keep their CSS in a `<style>` block within the same file.
- **No external CDN dependencies.** The flashcard app intentionally has zero external script/style imports.
- **Vanilla JavaScript only.** No frameworks (React, Vue, etc.) are used in this repo.
- **localStorage** is used for simple client-side persistence where needed.

## Working on This Repo

### Branching
- Production branch: `master` (auto-deployed to GitHub Pages)
- Feature work should be done on named branches and merged via PR

### Making Changes
1. Edit files directly — no compilation needed
2. Test by opening HTML files in a browser locally (simply open the file, no server required for most features)
3. Note: `localStorage`, `FileReader`, and some APIs require a server context — use `python3 -m http.server 8080` or similar for local testing of the flashcard app
4. Commit and push to your branch, then open a PR to `master`

### Adding New Experiments
- Add new `.html` files at the repo root
- Link to them from `index.html` in the `<section>` content area if you want them discoverable
- Follow the self-contained, no-external-dependencies pattern

## Notes for AI Assistants

- This repo has no linter, formatter, or test suite — there are no automated checks to run
- Do not introduce npm, build tooling, or external dependencies without explicit instruction
- When editing `styles.css`, be aware the Noto Sans fonts reference a `../fonts/` path that does not exist in the repo; this is intentional (font fallbacks handle it)
- `params.json` must not be deleted — it is used by the GitHub Pages infrastructure
- The `flashcard-test.html` markdown parser uses regex; edge cases in unusual markdown formatting may not parse correctly — this is a known limitation of the simple approach
